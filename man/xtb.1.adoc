XTB(1)
======
:doctype: manpage

// Modified by the o-xtb landscape task suite, 2026.

NAME
----

xtb - performs semiempirical quantummechanical calculations,
      for version 6.0 and newer

SYNOPSIS
--------

*xtb* ['OPTIONS'] 'FILE' ['OPTIONS']

DESCRIPTION
-----------

The `xtb(1)` program performs semiempirical quantummechanical calculations.
The underlying effective Hamiltonian is derived from density functional
tight binding (DFTB). This implementation of the xTB Hamiltonian is currently
compatible with the zeroth, first and second level parametrisation for
geometries, frequencies and non-covalent interactions (GFN)
as well as with the ionisation potential and
electron affinity (IPEA) parametrisation of the GFN1 Hamiltonian.
The generalized born (GB) model with solvent accessable surface area (SASA)
is also available in this version.
Ground state calculations for the simplified Tamm-Dancoff approximation (sTDA)
with the vTB model are currently not implemented.

GEOMETRY INPUT
~~~~~~~~~~~~~~

The wide variety of input formats for the geometry are supported by using
the mctc-lib. Supported formats are:

- Xmol/xyz files (xyz, log)
- Turbomole's coord, riper's periodic coord (tmol, coord)
- DFTB+ genFormat geometry inputs as cluster, supercell or fractional (gen)
- VASP's POSCAR/CONTCAR input files (vasp, poscar, contcar)
- Protein Database files, only single files (pdb)
- Connection table files, molfile (mol) and structure data format (sdf)
- Gaussian's external program input (ein)
- JSON input with `qcschema_molecule` or `qcschema_input` structure (json)
- FHI-AIMS' input files (geometry.in)
- Q-Chem molecule block inputs (qchem)

For a full list visit: https://grimme-lab.github.io/mctc-lib/page/index.html

`xtb(1)` reads additionally `.CHRG` and `.UHF` files if present.

INPUT SOURCES
-------------
`xtb(1)` gets its information from different sources. The one with highest
priority is the commandline with all allowed flags and arguments described below.
The secondary source is the `xcontrol(7)` system, which can in principle
use as many input files as wished. The `xcontrol(7)` system is the successor
of the set-block as present in version 5.8.2 and earlier. This implementation
of `xtb(1)` reads the `xcontrol(7)` from two of three possible sources,
the local xcontrol file or the 'FILE' used to specify the geometry
and the global configuration file found in the `XTBPATH`.

OPTIONS
-------

*-c, --chrg* 'INT':: 
    specify molecular charge as 'INT', overrides `.CHRG` file and `xcontrol` option

*-c, --chrg* 'INT:INT':: 
    specify charges for 'inner region:outer region' for `oniom` calculation, overrides `.CHRG` file and `xcontrol` option

*-u, --uhf* 'INT'::
    specify number of unpaired electrons as 'INT', overrides `.UHF` file and `xcontrol` option
    (default: 0 (singlet) for even electron number, 1 (doublet) for odd electron number)

*--gfn* 'INT'::
    specify parametrisation of GFN-xTB (default = 2)

*--gfnff, --gff* ::
    specify parametrisation of GFN-FF

*--tblite* ::
    use tblite library as implementation for xTB
    
*--ceh <grad> [REAL]* ::
      calculate CEH (Charge-Extended Hückel model) charges and write them to the ceh.charges file,
      optionally, calculate numerical gradients and write them to the ceh.charges.numgrad file
      with an adjustable step size for the numerical gradients.

*--ptb* ::
    performs single-point calculation with the density tight-binding method PTB.
    Provides electronic structure and properties, such as, e.g., atomic charges, bond orders, and dipole moments,
    but does not provide any energy-related properties, such as, e.g., total energy, nuclear gradients, or vibrational frequencies.

*--spinpol*::
    enables spin-polarization for xTB methods (tblite required)

*--oniom* 'METHOD' 'LIST'::
    use subtractive embedding via ONIOM method. 'METHOD' is given as `high:low`
    where `high` can be 'orca', 'turbomole', 'gfn2', 'gfn1', or 'gfnff' and
    `low` can be 'gfn2', 'gfn1', or 'gfnff'.
    The inner region is given as comma-separated indices directly in the commandline
    or in a file with each index on a separate line.

*--efield* 'REAL,REAL,REAL'::
    static electric field in Cartesian coordinates, overrides `.EFIELD` file,
    works only via tblite for the xTB Hamiltonians, or with GFN-FF and PTB.

*--etemp, --temp* 'REAL'::
    electronic temperature for SCC (default = 300K)

*--esp* ::
    calculate electrostatic potential on VdW-grid

*--stm* ::
    calculate STM image

*-a, --acc* 'REAL'::
    accuracy for SCC calculation, lower is better (default = 1.0)

*--iterations, --maxiterations* 'INT'::
    maximum number of SCC iterations per single point calculation (default = 250)

*--vparam* 'FILE'::
    Parameter file for xTB calculation

*--alpb* 'SOLVENT' ['STATE']::
    analytical linearized Poisson-Boltzmann (ALPB) model,
    available solvents are 'acetone', 'acetonitrile', 'aniline', 'benzaldehyde',
    'benzene', 'ch2cl2', 'chcl3', 'cs2', 'dioxane', 'dmf', 'dmso', 'ether',
    'ethylacetate', 'furane', 'hexandecane', 'hexane', 'methanol', 'nitromethane',
    'octanol', 'woctanol', 'phenol', 'toluene', 'thf', 'water'.
    The solvent input is not case-sensitive.
    The Gsolv reference state can be chosen as 'reference', 'bar1M', or 'gsolv' (default).

*-g, --gbsa* 'SOLVENT' ['STATE']::
    generalized born (GB) model with solvent accessable surface (SASA) model,
    available solvents are 'acetone', 'acetonitrile', 'benzene' (only GFN1-xTB),
    'CH2Cl2', 'CHCl3', 'CS2', 'DMF' (only GFN2-xTB), 'DMSO', 'ether', 'H2O',
    'methanol', 'n-hexane' (only GFN2-xTB), 'THF' and 'toluene'.
    The solvent input is not case-sensitive.
    The Gsolv reference state can be chosen as 'reference', 'bar1M', or 'gsolv' (default).

*--gbe* 'SOLVENT/EPSILON'::
    generalized Born for finite epsilon (GBe) solvation model (tblite required),
    includes only the electrostatic solvation contribution (no SASA model),
    available solvents are all solvents that are available for alpb.
    Additionally, the dielectric constant can be set manually.

*--gb* 'SOLVENT/EPSILON'::
    generalized Born (GB) solvation model (tblite required),
    includes only the electrostatic solvation contribution (no SASA model),
    available solvents are all solvents that are available for alpb.
    Additionally, the dielectric constant can be set manually.

*--cosmo* 'SOLVENT/EPSILON'::
    domain decomposition conductor-like screening model (ddCOSMO)
    available solvents are all solvents that are available for alpb.
    Additionally, the dielectric constant can be set manually or an ideal conductor
    can be chosen by setting epsilon to infinity.
    
*--tmcosmo* 'SOLVENT/EPSILON'::
    same as --cosmo, but uses TM convention for writing the .cosmo files.

*--cpcmx* 'SOLVENT'::
    extended conduction-like polarizable continuum solvation model (CPCM-X),
    available solvents are all solvents included in the Minnesota Solvation Database.

*--cma* ::
    shifts molecule to center of mass and transforms cartesian coordinates
    into the coordinate system of the principle axis (not affected by
    `isotopes`-file).

*--pop*::
    requests printout of Mulliken population analysis

*--molden*::
    requests printout of molden file

*--alpha* ::
    requests the extension of electrical properties to static molecular dipole polarizabilities

*--raman* ::
    requests Raman spectrum calculation via combination of GFN2-xTB and PTB
    using the temperature 'REAL' (default 298.15 K) and the wavelength of 
    the incident laser which must be given in nm 'REAL' (default 514 nm)
    
*--dipole*::
    requests dipole printout

*--wbo*::
    requests Wiberg bond order printout

*--lmo*::
    requests localization of orbitals

*--fod*::
    requests FOD calculation

*--cycles* 'INT'::
    maximum number of optimization cycles

*--method* 'NAME'::
    select the method of the current landscape run type; the value domain is
    filtered by the run type and an unknown or mismatched name aborts the run.
    `--lopt` and `--lscan` accept the minimisers sd, cg, lbfgs, bfgs, diis, rfo;
    `--lts` accepts the saddle searches prfo, bprfo, dimer, neb, cineb, autoneb,
    string, gsm; `--lirc` accepts the integrators gs, hpc, lqa, eulerpc; `auto`
    keeps the default of the task.  With `-o, --opt` and `--ohess` the native
    engines ancopt (alias rf), lancopt (alias l-ancopt), fire (alias inertial)
    and pbc_lbfgs are accepted, and a landscape minimiser selects the suite
    that the redeployed `--opt` runs.  `--method` is the canonical name of
    `--lopt-engine`, `--lscan-method`, `--lts-method` and `--lirc-method`.
    The name is not case-sensitive.

RUNTYPS

NOTE: You can only select *one* runtyp, only the first runtyp will be used
      from the program, use implemented composite runtyps to perform several
      operations at once.

*--scc, --sp*::
    performs a single point calculation

*--vip*::
    performs calculation of ionisation potential.
    This needs the .param_ipea.xtb parameters
    and a GFN1 Hamiltonian.

*--vea*::
    performs calculation of electron affinity.
    This needs the .param_ipea.xtb parameters
    and a GFN1 Hamiltonian.

*--vipea*::
    performs calculation of electron affinity and ionisation potential.
    This needs the .param_ipea.xtb parameters
    and a GFN1 Hamiltonian.

*--vfukui*::
    performs calculation of Fukui indices.

*--vomega*::
    performs calculation of electrophilicity index.
    This needs the .param_ipea.xtb parameters
    and a GFN1 Hamiltonian.

*--grad*::
    performs a gradient calculation

*-o, --opt* ['LEVEL']::
    run the landscape suite geometry optimization (pass `--method ancopt`
    for the native `ancopt(3)`),
    levels from crude, sloppy, loose, normal (default), tight, verytight
    to extreme can be chosen

*--lopt*::
    minimise the geometry with the landscape task suite (`src/landscape`); the
    algorithm is selected with `--method` (alias `--lopt-engine`) and the
    thresholds with `--lopt-level`.  The sub-options are in SUITE OPTIONS

*--lscan*::
    scan an internal coordinate (distance, angle or dihedral) with the
    landscape task suite; the result is written to `xtbscan.log` with the
    de-biased energy of every frame.  The sub-options are in SUITE OPTIONS

*--lts*::
    transition state search with the landscape task suite; the method is
    selected with `--method` (alias `--lts-method`), one of prfo (default),
    bprfo, dimer, neb, cineb, autoneb or string (alias gsm).  Writes `xtbts.xyz`
    and `xtbts.log` and confirms the imaginary mode count.  The sub-options are
    in SUITE OPTIONS

*--lirc*::
    intrinsic reaction coordinate with the landscape task suite; the input
    geometry is the transition state and must have exactly one imaginary mode.
    The integrator is selected with `--method` (alias `--lirc-method`), one of
    hpc (default), lqa, eulerpc or gs.  Writes `irc_forward.xyz`,
    `irc_backward.xyz`, `irc_path.xyz` and `irc.log`.  The sub-options are in
    SUITE OPTIONS

*--lvib*::
    harmonic frequencies, normal modes and thermochemistry with the landscape
    task suite; writes `vibspectrum`, `vib_normal_modes`, `g98.out` and
    `hessian` with the names and formats of `--hess`.  The sub-options are in
    SUITE OPTIONS

*--ljson*::
    write the structured result `landscape_<task>.json` (status, counters and
    convergence history) for every landscape task; the switch needs one of
    `--lopt`, `--lscan`, `--lts`, `--lirc`, `--lvib`, `--opt` or `--ohess`

*--hess*::
    perform a numerical hessian calculation on input geometry
    
*--ohess* ['LEVEL']::
    perform a numerical hessian calculation on a geometry optimized by the
    landscape suite (pass `--method ancopt` for the native `ancopt(3)`
    optimizer)

*--bhess* ['LEVEL']::
    perform a biased numerical hessian calculation on an `ancopt(3)` optimized
    geometry

    Hessian runs automatically perform a compliance analysis for nonperiodic
    systems with more than one atom and no frozen atoms.

*--o1nh*::
    perform the numerical hessian calculation using the ODLR approximation (O1NumHess)

*--imagmin* 'REAL'::
    magnitudes below this value (cm⁻¹) are ignored in the O1NumHess
    imaginary frequency repair (default 5).

*--imagmax* 'REAL'::
    deepest imaginary frequency (cm⁻¹) considered in the O1NumHess
    imaginary frequency repair (default 200).

*--md*::
    molecular dynamics simulation on start geometry

*--metadyn* ['int']::
    meta dynamics simulation on start geometry, saving 'int' snapshots
    of the trajectory to bias the simulation

*--omd*::
    molecular dynamics simulation on `ancopt(3)` optimized geometry,
    a loose optimization level will be chosen

*--metaopt* ['LEVEL']::
    call `ancopt(3)` to perform a geometry optimization,
    then try to find other minimas by meta dynamics

*--path* ['FILE']::
    use meta dynamics to calculate a path from the input geometry
    to the given product structure

*--reactor*::
    experimental

*--modef* 'INT'::
    modefollowing algorithm. 'INT' specifies the mode that should be
    used for the modefollowing.

*--dipro* ['REAL']:: 
    the dimer projection method for the calculation of electronic coupling integrals between two fragments.
    'REAL' sets the threshold for nearly degenerate orbitals to still be considered (default = 0.1 eV).
    

SUITE OPTIONS
-------------

The landscape task suite (`src/landscape`) is selected by one of the run
types `--lopt`, `--lscan`, `--lts`, `--lirc` or `--lvib` (see RUNTYPS
above), and by the redeployed `--opt` and `--ohess`; the sub-options below
configure the selected task and the common `--ljson` switch is listed with
the run types. Every sub-option selects a landscape run type itself, so
combining one with a native run type is a **run type conflict** and aborts
during argument parsing (`xtb mol.xyz --sp --lscan-fc 0.05` fails with a run type
conflict naming `--scc` and `--lscan-fc`); the native run types do not ignore
these options, they never get that far. `--opt` and `--ohess` take the suite's
`--method`, `--cycles`, `--acc` and `--ljson` but not the per-task sub-options.

The suite keeps every quantity in atomic units internally and converts at
the input boundary. Unless an option says otherwise a length is in bohr, an
energy in hartree, a gradient or force in hartree/bohr, a Hessian element in
hartree/bohr^2 and a stiffness in hartree/bohr^2. The exceptions are
spelled out at their options: a scanned coordinate uses angstrom (distance)
or degree (angle and dihedral), the two dimer lengths and every trust radius
are Cartesian bohr, the IRC arc lengths are in `bohr*amu^1/2` (mass weighted
arc length, one atomic unit) and the frequency cutoffs are in `cm^-1`.

`--method` (see OPTIONS) is the canonical spelling of `--lopt-engine`,
`--lscan-method`, `--lts-method` and `--lirc-method`: the same value through
two of the flags is idempotent, a different value aborts the run, and an
unknown name or a name of another task is an error. Every name is matched
case insensitively.

MINIMISATION OPTIONS (--lopt)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

*--lopt-engine* 'NAME'::
    minimisation algorithm of the suite, one of `sd`, `cg`, `lbfgs` (default),
    `bfgs`, `diis` or `rfo`. Alias of `--method`; the name is not case-sensitive.
    Because the native `--opt` runs `ancopt(3)`, the active default engine is
    echoed as a notice unless the flag is given.

*--lopt-level* 'LEVEL'::
    convergence level, one of `superloose`, `loose`, `normal` (default), `tight`
    or `vtight`; not case-sensitive. One level drives four axes at once: the four
    thresholds (maximum and RMS gradient in hartree/bohr, maximum and RMS
    displacement in bohr), the energy tolerance `e_tol` (hartree), the SCC
    accuracy of the engine and the multiplier of the step budget (3 steps per
    atom at `normal`, clamped to 200..10000).

*--lopt-hessian* 'SOURCE'::
    Hessian backend, one of `numerical` (default; the suite's own central
    differences of the electronic gradient), `model` (Lindh-D2 model Hessian from
    `src/model_hessian`) or `file` (read the TURBOMOLE layout written by an
    earlier run, see `--lopt-hessian-file`).

*--lopt-max-steps* 'N'::
    step budget of the minimisation. The default is derived from the convergence
    level (3 steps per atom, clamped to 200..10000); `--cycles` and the level
    change it. A budget given here wins over the level-derived value.

*--lopt-hess-step* 'VALUE'::
    finite difference step of the numerical Hessian in bohr (default 0.005). Only
    `--lopt-engine rfo` builds a numerical Hessian; the other five engines
    (including the default `lbfgs`) never do, and the value is ignored for
    `--lopt-hessian model` or `file`. The run then echoes the effective value and
    marks it as not used.

*--lopt-sccacc* 'VALUE'::
    SCC accuracy of the displaced single points of the numerical Hessian
    (default 0.3). Consumed by the same engine and Hessian source as
    `--lopt-hess-step`.

*--lopt-restart* 'MODE'::
    wavefunction restart policy of the engine, `off` (default), `pin` or `warm`.

*--lopt-hessian-file* 'NAME'::
    file read by `--lopt-hessian file` (TURBOMOLE `$hessian` layout, the
    `hessian` file written by `--hess` and by `--lvib`). The name is used only by
    the `file` source: with `numerical` or `model` it is silently discarded and
    never echoed (a registered, deliberately unfixed honesty gap).

SCAN OPTIONS (--lscan)
~~~~~~~~~~~~~~~~~~~~~~

*--lscan-coord* 'TYPE'::
    type of the first scanned coordinate, one of `distance` (default), `angle` or
    `dihedral`; not case-sensitive.

*--lscan-atoms* 'LIST'::
    1-based atom indices of the first coordinate, comma or blank separated (two
    for a distance, three for an angle, four for a dihedral).

*--lscan-step* 'VALUE'::
    step size of the first coordinate in angstrom (distance) or degree (angle and
    dihedral).

*--lscan-nstep* 'N'::
    number of steps of the first coordinate; a sweep visits the coordinate
    values `q0 + k step` for `k = 0..nstep`, in both directions unless
    `--lscan-oneway` is given.

*--lscan-coord2, --lscan-atoms2, --lscan-step2, --lscan-nstep2*::
    the same four options for a second scanned coordinate; any of them switches
    the scan to a two-dimensional Cartesian product grid (as `--lscan-ndim 2`).

*--lscan-mode* 'MODE'::
    scan mode, `relaxed` (default; every point is minimised under a constraint
    potential) or `rigid` (the geometry is constructed and a single point is
    evaluated); not case-sensitive.

*--lscan-method* 'NAME'::
    inner minimiser of a relaxed scan, one of `sd`, `cg`, `lbfgs` (default),
    `bfgs`, `diis` or `rfo`. Alias of `--method`; not case-sensitive.

*--lscan-level* 'LEVEL'::
    convergence level of the inner minimisation, one of `superloose`, `loose`,
    `normal` (default), `tight` or `vtight`.

*--lscan-ndim* 'N'::
    number of scanned coordinates, 1 (default) or 2.

*--lscan-restart* 'MODE'::
    wavefunction policy of the engine at every scan point, `off` (default), `pin`
    or `warm`. `off` and `pin` reset the incoming wavefunction from the stored
    reference, `warm` **keeps** it, so `warm` carries the SCF history of the
    previous point into the next one (measured: reusing the wavefunction moves
    the gradient by about 4e-7 hartree/bohr, which is why the suite keeps the
    policy uniform inside one evaluation sequence). The geometry warm start is a
    separate mechanism, `warm_start`, which is on by default and reuses the
    previous point's geometry.

*--lscan-oneway*::
    scan the forward branch only; no reverse branch and no hysteresis report.

*--lscan-cold-start*::
    start every scan point from the input geometry instead of the geometry of the
    previous point.

*--lscan-fc* 'VALUE'::
    force constant of the constraint bias potential (the coordinate deviation
    raised to the power `--lscan-expo` and scaled by this value) in
    hartree/bohr^2 (default 0.5). This is ten times the xtb scan force constant
    `fcconstr = 0.05` of the `$scan` block, so the active default is echoed as a
    notice unless the flag is given; use `--lscan-fc 0.05` when compatibility with
    existing `xtbscan.log` tool chains matters.

*--lscan-expo* 'VALUE'::
    exponent of the constraint potential (default 2.0). Only distance constraints
    use it: an angle is biased by the squared angular deviation and a dihedral
    by `(1 - cos dphi)`, both scaled by the same force constant and bounded by
    twice it, with a zero torque at 180 degree.

*--lscan-max-steps* 'N'::
    step budget of the inner relaxation of every scan point; derived from the
    convergence level like `--lopt-max-steps`.

*--lscan-hess-step* 'VALUE'::
    finite difference step of the numerical Hessian of the scan points in bohr
    (default 0.005). Only `--lscan-method rfo` builds one (the default `lbfgs`
    never does), a rigid scan has no inner minimisation at all, and the value is
    ignored for `--lscan-hessian model` or `file`.

*--lscan-sccacc* 'VALUE'::
    SCC accuracy of the displaced single points of the numerical Hessian
    (default 0.3); consumed by the same inner minimiser and Hessian source as
    `--lscan-hess-step`.

*--lscan-hessian* 'SOURCE'::
    Hessian backend of the scan points, one of `numerical` (default), `model` or
    `file`.

*--lscan-hessian-file* 'NAME'::
    file read by `--lscan-hessian file` (TURBOMOLE layout); silently discarded
    when the source is not `file`.

TRANSITION STATE OPTIONS (--lts)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

*--lts-method* 'NAME'::
    search method, one of `prfo` (default), `bprfo` (restricted step), `dimer`
    (first derivatives only, no Hessian), `neb`, `cineb` (climbing image NEB),
    `autoneb` (incremental path building) or `string`/`gsm` (growing string).
    Alias of `--method`; not case-sensitive. `neb`, `cineb`, `autoneb`, `string`
    and `gsm` are chain-of-states methods and need `--lts-product`.

*--lts-trust* 'VALUE'::
    initial trust radius of the step in bohr (default 0.37795).

*--lts-trust-max* 'VALUE'::
    upper bound of the trust radius in bohr (default 1.8897).

*--lts-hlow* 'VALUE'::
    curvature floor of the downhill modes in hartree/bohr^2 (default 0.01).

*--lts-max-steps* 'N'::
    maximum number of macro iterations; derived from the convergence level (3
    steps per atom, clamped to 200..10000).

*--lts-level* 'LEVEL'::
    convergence level (thresholds, energy tolerance, SCC accuracy and step
    budget), one of `superloose`, `loose`, `normal` (default), `tight` or `vtight`.

*--lts-mode-overlap-min* 'VALUE'::
    mode following guard: reselect the transition vector below this overlap
    (default 0.3). The value is the dimensionless `|V^T v|` overlap.

*--lts-alpha* 'VALUE'::
    fraction of the trust radius assigned to the uphill subspace by `bprfo`
    (default 0.5).

*--lts-micro-cycles* 'N'::
    maximum number of restricted step micro iterations (default 50).

*--lts-target-mode* 'N'::
    which negative mode is followed, 1 = most negative (default 1).

*--lts-init-mode* 'MODE'::
    initial transition vector, `h0` (most negative Hessian mode, default) or
    `force` (largest Cartesian gradient component direction).

*--lts-escape-step* 'VALUE'::
    displacement along the lowest internal mode in bohr (default 0.2), applied
    when the start geometry is a minimum so that P-RFO has a direction to ascend
    along; 0 disables the escape. The active default is echoed as a notice unless
    the flag is given. The full walk budget is 3.0 bohr.

*--lts-delta* 'VALUE'::
    dimer separation, the distance of each image from the common midpoint in bohr
    (default 0.018897, i.e. 0.01 angstrom; this is the pysisyphus convention, not
    the VASP `DdR` that denotes twice the value).

*--lts-dr* 'VALUE'::
    finite difference step of the dimer translation probe in bohr (default
    0.0018897).

*--lts-rot-max-iter* 'N'::
    maximum number of dimer rotations per macro iteration (default 5).

*--lts-rot-alpha* 'VALUE'::
    damping of the dimer rotation angle (default 0.5; 1 = undamped).

*--lts-rot-frms* 'VALUE'::
    RMS torque below which the dimer rotation has converged, in hartree/bohr
    (default 2.65e-4).

*--lts-ninit* 'MODE'::
    initial dimer axis, `random` (default, seeded by `--lts-seed`) or `force`
    (largest Cartesian gradient component direction).

*--lts-seed* 'N'::
    seed of the random initial dimer axis (default 42). The generator state is
    reset from this seed before every draw, so a run is exactly reproducible.

*--lts-step-max* 'VALUE'::
    maximum dimer translation step in bohr (default 0.28346).

*--lts-step0* 'VALUE'::
    upper bound of the first dimer translation in bohr (default 0.37795); the
    `dR` curvature probe can shorten the actual first displacement.

*--lts-translate-max-iter* 'N'::
    maximum number of quick-min displacement updates per dimer translation
    (default 1).

*--lts-recalc* 'N'::
    recompute the exact Hessian every N macro steps, 0 disables (default 1).

*--lts-no-verify*::
    skip the frequency confirmation of the located stationary point.

*--lts-no-rigid*::
    keep the rigid body (translation and rotation) components in the Cartesian
    step instead of projecting them out.

*--lts-restart* 'MODE'::
    wavefunction restart policy of the engine, `off` (default), `pin` or `warm`.

*--lts-hessian* 'SOURCE'::
    Hessian backend, one of `numerical` (default), `model` (Lindh-D2) or `file`.

*--lts-hessian-file* 'NAME'::
    file read by `--lts-hessian file` (TURBOMOLE layout); silently discarded when
    the source is not `file`.

*--lts-hess-step* 'VALUE'::
    finite difference step of the numerical confirmation Hessian in bohr
    (default 0.005); the canonical name of `--lts-step`.

*--lts-step* 'VALUE'::
    alias of `--lts-hess-step`. If the confirmed mode lies within
    `0 +/- 3 cm^-1`, the curvature sign is re-decided with 0.002 bohr and SCC
    accuracy 0.1.

*--lts-sccacc* 'VALUE'::
    SCC accuracy of the displaced single points of the confirmation Hessian
    (default 0.3).

*--lts-product* 'NAME'::
    product endpoint of a chain-of-states search (`neb`, `cineb`, `autoneb`,
    `string`, `gsm`): a single frame xyz with the same atoms in the same order;
    the positional input file is the reactant.

*--lts-images* 'N'::
    number of images of a band, the two fixed endpoints included (default 9); for
    `autoneb` it is the requested final number of images.

*--lts-kmin, --lts-kmax* 'VALUE'::
    lower and upper spring constant of the dynamic springs in hartree/bohr^2
    (defaults 1e-2 and 1e-1, calibrated on the analytic LEPS surface).

*--lts-kdecay* 'VALUE'::
    decay factor of the dynamic spring formula (default 0.5).

*--lts-no-dynamic-k*::
    use the single spring constant `kmax` for every image.

*--lts-climb*::
    switch on the climbing image stage (CI-NEB); implied by `--lts-method cineb`,
    `autoneb`, `string` and `gsm`.

*--lts-climb-switch* 'VALUE'::
    band force in hartree/bohr below which the climbing image is ignited (default
    9.7234e-3, the standard 0.5 eV/angstrom).

*--lts-no-idpp*::
    straight linear interpolation instead of the IDPP initial path.

*--lts-no-align*::
    do not Kabsch align the images before every band evaluation.

*--lts-relax-ends*::
    relax the two endpoints with the minimiser before the search.

*--lts-max-displ* 'VALUE'::
    upper bound of one displacement component of a band step in bohr
    (default 0.37795).

*--lts-frms-avg, --lts-frms-max* 'VALUE'::
    band convergence thresholds of the average and the largest per-image force
    RMS in hartree/bohr (defaults 3e-4 and 1e-3).

*--lts-autoneb-nstart* 'N'::
    number of images of the coarse start path of an AutoNEB run (default 5).

*--lts-autoneb-max-paths* 'N'::
    hard upper bound of the number of images of an AutoNEB path (default 10); a
    request above it is an error, never a silent truncation.

*--lts-autoneb-max-depth* 'N'::
    hard upper bound of the number of image insertion stages (default 5).

*--lts-autoneb-restart* 'NAME'::
    multi-frame xyz path of an earlier AutoNEB run (its `path_autoneb.xyz`),
    adopted as the initial path so the completed stages are not repeated.

*--lts-string-nnodes* 'N'::
    target number of nodes of the growing string, endpoints included (default 9).
    The string is configured here, not by `--lts-images`.

*--lts-string-grow-tol* 'VALUE'::
    norm threshold of the growth indicator in hartree/bohr (default 5e-3).

*--lts-string-ds* 'VALUE'::
    arc length increment of one growth step of the string in bohr (default 0.5).

*--lts-string-nu2* 'VALUE'::
    curvature floor for the node spacing condition, in hartree/bohr^2
    (default 0.05).

*--lts-string-grow-steps* 'N'::
    maximum perpendicular relaxation iterations of one frontier node (default
    200).

*--lts-no-string-spline*::
    central difference tangents of the string instead of the cubic spline
    tangent.

*--lts-string-history*::
    print the growth history (position and perpendicular force of every node);

INTRINSIC REACTION COORDINATE OPTIONS (--lirc)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

*--lirc-method* 'NAME'::
    integration method, one of `hpc` (Hessian based predictor-corrector,
    default), `lqa` (Page-McIver analytic quadratic propagation, the cheapest),
    `eulerpc` (Euler predictor-corrector) or `gs` (Gonzalez-Schlegel sphere
    relaxation). Alias of `--method`; not case-sensitive. The active default is
    echoed as a notice unless the flag is given.

*--lirc-step* 'VALUE'::
    step length of one macro step in `bohr*amu^1/2` (mass weighted arc length,
    default 0.10; use 0.05 for a tight path). The clean range is 0.05-0.15 for
    `--lirc-method gs`, whose macro step stalls in a two cycle from 0.20 on;
    `hpc` and `eulerpc` are correct at 0.20. The limit cycle guard only detects
    the cancelling subclass of the stall: a large step can still end far from the
    minimum (measured 0.236 bohr at 0.40 forward).

*--lirc-max-steps* 'N'::
    maximum number of macro steps of one direction; derived from the convergence
    level (3 steps per atom, clamped to 200..10000).

*--lirc-level* 'LEVEL'::
    convergence level of the endpoint relaxation (thresholds, energy tolerance,
    SCC accuracy and step budget), one of `superloose`, `loose`, `normal`
    (default), `tight` or `vtight`. The IRC path itself is left by the termination
    signals `--lirc-grad-tol` and `--lirc-e-rise`.

*--lirc-swap*::
    exchange the forward and the backward direction defined by the phase
    convention.

*--lirc-oneway*::
    integrate the forward direction only.

*--lirc-target-mode* 'N'::
    which negative mode defines the initial direction, 1 = most negative
    (default 1).

*--lirc-micro-cycles* 'N'::
    maximum number of Gonzalez-Schlegel micro cycles per macro step (default 20).

*--lirc-micro-thresh* 'VALUE'::
    convergence threshold of the sphere relaxation in `bohr*amu^1/2` (default
    1e-3).

*--lirc-euler-n* 'N'::
    Euler/Simpson substeps of the analytic LQA propagation (default 5000).

*--lirc-loose-cycles* 'N'::
    EulerPC coarse phase: use the plain Euler prediction for the first N macro
    steps, 0 disables the coarse phase (default 3).

*--lirc-mbs-tol* 'VALUE'::
    acceptance threshold of the modified Bulirsch-Stoer corrector in
    `bohr*amu^1/2` (default 1e-5; the HPC paper uses 1e-6).

*--lirc-mbs-max-k* 'N'::
    maximum extrapolation level of the modified Bulirsch-Stoer corrector
    (default 15).

*--lirc-mbs-points* 'N'::
    base number of Euler substeps of the modified Bulirsch-Stoer corrector
    (default 20).

*--lirc-dwi-n* 'N'::
    capacity of the DWI surface fit (default 4). The implemented interpolant is
    two point by construction, so every N >= 2 is behaviourally equivalent; N < 2
    is rejected.

*--lirc-e-rise* 'N'::
    termination signal (c): stop after N consecutive rising energies (default 3).
    A large N does not guarantee running to the step budget; the limit cycle guard
    `--lirc-osc-window` is an independent signal.

*--lirc-erise-steps* 'N'::
    alias of `--lirc-e-rise`.

*--lirc-grad-tol* 'VALUE'::
    termination signal (b): stop when the RMS gradient per Cartesian component
    falls below this value in hartree/bohr (default 1e-3).

*--lirc-osc-window* 'N'::
    limit cycle guard of the `gs` macro step: leave the path after N consecutive
    macro steps that cancel each other (default 8; 0 disables the guard). The
    guard is inert on every validated path and truncates the stalled walk; the
    endpoint it returns is one phase of the oscillation, about one step length
    away from the minimum, so the run is reported as incomplete. Only
    `--lirc-method gs` is affected.

*--lirc-adaptive*::
    opt-in adaptive step length of the `gs` macro step (default off): halve the
    effective step length (floor: a sixteenth of `--lirc-step`) at the first
    cancelling macro step pair. It changes the validated small step paths and is
    therefore a re-baseline; every reduction is printed. Only `--lirc-method gs`
    honours it - every other method silently ignores it.

*--lirc-recalc* 'N'::
    rebuild the exact Hessian every N macro steps, -1 disables (default -1). Pure
    Bofill updates are sufficient for short paths; long or strongly curved paths
    drift and need an explicit `--lirc-recalc 5 .. 10`.

*--lirc-no-endpoint-relax*::
    do not relax the two endpoints to assign them to a minimum; the
    `--lirc-rmsd-end` criterion is then skipped (and reported as skipped).

*--lirc-endpoint-relax*::
    relax the two endpoints to assign them to a minimum (default; the explicit
    flag restores it after a `--lirc-no-endpoint-relax`).

*--lirc-rmsd-end* 'VALUE'::
    Kabsch aligned RMSD between an endpoint and its relaxed minimum below which
    the endpoint counts as having reached a minimum, in bohr (default 0.18897).

*--lirc-hessian* 'SOURCE'::
    Hessian backend, one of `numerical` (default), `model` (Lindh-D2) or `file`.

*--lirc-hessian-file* 'NAME'::
    file read by `--lirc-hessian file` (TURBOMOLE layout); silently discarded
    when the source is not `file`.

*--lirc-hess-step* 'VALUE'::
    finite difference step of the numerical Hessian in bohr (default 0.005); the
    canonical name of `--lirc-step-hess`, not to be confused with `--lirc-step`
    (the arc length of the reaction path).

*--lirc-step-hess* 'VALUE'::
    alias of `--lirc-hess-step`.

*--lirc-sccacc* 'VALUE'::
    SCC accuracy of the displaced single points of the Hessian (default 0.3).

*--lirc-restart* 'MODE'::
    wavefunction restart policy of the engine, `off` (default), `pin` or `warm`.

FREQUENCY AND THERMOCHEMISTRY OPTIONS (--lvib)
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

*--lvib-hessian* 'SOURCE'::
    Hessian backend of the frequency task, one of `numerical` (default), `model`
    (Lindh-D2) or `file` (read the Hessian of an earlier run).

*--lvib-hessian-file* 'NAME'::
    file read by `--lvib-hessian file` (TURBOMOLE layout). Unlike the other
    tasks, `--lvib` prints the name even when the source is not `file`, but it
    still only reads it for `file`.

*--lvib-hess-step* 'VALUE'::
    finite difference step of the numerical Hessian in bohr (default 0.005); the
    canonical name of `--lvib-step`.

*--lvib-step* 'VALUE'::
    alias of `--lvib-hess-step`.

*--lvib-sccacc* 'VALUE'::
    SCC accuracy of the displaced single points of the numerical Hessian
    (default 0.3).

*--lvib-restart* 'MODE'::
    wavefunction restart policy of the engine, `off` (default), `pin` or `warm`.
    The finite difference sequence resets the wavefunction to the state it entered
    the Hessian with before every displacement, so `warm` and `pin` hand the
    provider the same start and produce a byte identical `hessian` file; only
    `off` is distinguishable.

*--lvib-odlr*::
    request the ODLR approximation. Not implemented: the run reports the request
    and the dense provider refuses it - the Hessian is always built in full.

*--lvib-no-project*::
    do not project the translations and rotations out of the Hessian.

*--lvib-temp* 'VALUE'::
    temperature of the thermodynamic table in K (default 298.15). An explicit
    value overrides the xcontrol `$thermo temp` key, which overrides the builtin
    default.

*--lvib-rotor-cutoff* 'VALUE'::
    rotor cutoff of the quasi-RRHO entropy treatment in `cm^-1` (default 50.0;
    the xcontrol `$thermo sthr` key).

*--lvib-imag-cutoff* 'VALUE'::
    imaginary frequency cutoff in `cm^-1` (default -20.0; the minus sign is
    required). The value sets both the mode counting and, together with the
    xcontrol `$thermo imagthr` key, the partition function of the thermochemistry.

*--lvib-freq-scal* 'VALUE'::
    frequency scaling factor of the thermochemistry (default 1.0; the xcontrol
    `$thermo scale` key).

ENVIRONMENT VARIABLES
---------------------
`xtb(1)` accesses a path-like variable to determine the location of its
parameter files, you have to provide the `XTBPATH` variable in the same
syntax as the system `PATH` variable. If this variable is not set, `xtb(1)`
will try to generate the `XTBPATH` from the deprecated `XTBHOME` variable.
In case the `XTBHOME` variable is not set it will be generated from the
`HOME` variable. So in principle storing the parameter files in the users
home directory is suffient but might lead to come cluttering.

Since the `XTBHOME` variable is deprecated with version 6.0 and newer
`xtb(1)` will issue a warning if `XTBHOME` is not part of the `XTBPATH`
since the `XTBHOME` variable is not used in production runs.

`OMP_NUM_THREADS` sets the number of OpenMP threads. A threaded BLAS is the
largest performance trap on multi core machines: the OpenMP threads and the BLAS
thread pool multiply, and an idle pool spins between calls. Measured on a 24 atom
GFN2 single point at `OMP_NUM_THREADS=8`, the settings that recover the loss
differ in strength, and the strongest one comes first:

. *before the process starts*, `export OPENBLAS_NUM_THREADS=1` (19 ms). The
  environment variable is consumed while the OpenBLAS pool is created, in an ELF
  constructor that runs before `main()`, so the shell has to export it - the
  program cannot set it in time.
. Next, *--blas-threads* 'N' together with `OMP_WAIT_POLICY=PASSIVE` or
  `GOMP_SPINCOUNT=0` (25 ms / 23 ms; both are read at start-up as well). The flag
  alone measures 102 ms, 5.4x the environment variable: it resizes the work
  partition of the pool through the runtime API, but the pool itself was already
  built at eight threads before `main()`, and what remains is the OpenMP teams
  spinning between the calls, which is exactly what the wait policy and the spin
  count control. Leaving everything at its default measures 663 ms.
. The larger the system, the smaller the gap: at 501 atoms, where the serial
  matrix work dominates, *--blas-threads 1* measures 1.8x the
  `OPENBLAS_NUM_THREADS=1` time (1285 ms against 705 ms). On a large system the
  pool should therefore stay threaded - pinning it to one thread is a loss
  there - and `OMP_WAIT_POLICY=PASSIVE` with the pool left at the thread count
  measured best.

`MKL_NUM_THREADS` is ignored by a build linked against OpenBLAS and
`OPENBLAS_DEFAULT_NUM_THREADS` measured a no-op.

The same limit can be requested from inside the program, without any
environment variable, with *--blas-threads* 'N': it calls the OpenBLAS (or
MKL) runtime API through `dlopen`/`dlsym`, prints the thread count it read back
from the backend and warns with `no OpenBLAS or MKL symbol found` when the
linked backend exports no such symbol. That warning also covers a
*statically* linked BLAS: its symbols exist only in `.symtab`, which is never
part of the dynamic lookup scope, so the flag has no effect there although the
symbol is present in the binary. Without the flag `xtb(1)` changes nothing.

Both API pairs are resolved by symbol name: `openblas_set_num_threads` with its
getter `openblas_get_num_threads`, and the oneMKL pair `mkl_set_num_threads` /
`mkl_get_max_threads` (the function `threadpoolctl` reads MKL's thread count
with). MKL support is therefore written against the documented oneMKL names; no
MKL is installed on the machine this option was developed on, so the MKL branch has
never been executed against a real oneMKL; it was exercised with stub symbols only,
and the OpenBLAS branch is the one verified by running it.
*--blas-threads* and *-P, --parallel* are different knobs (*--parallel* sets the
OpenMP thread count and, under an MKL build, the MKL pool as well); where both
reach the same pool the flag that appears last on the command line wins.

`OMP_STACKSIZE` sets the stack size of the OpenMP worker threads - not the stack
of the main thread, and not the same setting as `ulimit -s`, although the
process stack limit does size the worker stacks too: measured, the worker threads
get 2 MiB while `ulimit -s` is `unlimited` (glibc falls back to the pthread
default) and the stock `ulimit -s 8192` gives them 8 MiB, so the `unlimited`
setting is the smaller of the two. This matters because the GFN0 charge model can
need a worker stack that grows with the system size: in the OpenMP loop over the
Coulomb derivative `getCoulombDerivsCluster`, the array reduction
`reduction(+:djdr, djdtr, djdL)` makes the compiler place each thread's private
copy of the reduction arrays on the thread stack, `24*nat*(nat+1) + 96*(nat+1)`
bytes for `nat` atoms, about `24*nat^2` bytes - 6 060 096 bytes, about 6 MB, at
500 atoms. When that does not fit, the thread writes into its guard page and the
process dies with `SIGSEGV`. There is no warning and no usable backtrace:
measured, the run is completely silent at the smallest sizes that crash (0 bytes
on stderr), and the single frame the runtime resolves is `gomp_thread_start`
inside libgomp. The size at which this happens is a property of the environment
and not of the code: measured with two threads, the first size that crashes is
about 290 atoms with a 2 MiB worker stack and about 588 atoms with the stock
8 MiB one, while the formula above is the portable statement. `--gfn 0` reaches
the limit first (GFN1, GFN2 and GFN-FF ran clean at 500 and 598 atoms, and GFN2
also at 1001 atoms, with the same thread counts), but this is a stack size issue
and not a method issue: with `ulimit -s 4096` even a single threaded run of the
same system crashes. The workaround is `export OMP_STACKSIZE=512M`, or a larger
process stack limit such as `ulimit -s 65536`; it was verified at 290 and 500
atoms and with the official 6.7.1 binary, where the parallel run then reproduces
the serial energy. A fixed generous value is enough, because the requirement
grows with the atom count; *--help* suggests `export OMP_STACKSIZE=4G`.

WARNINGS
--------
`xtb(1)` can generate the two types of warnings, the first warning section
is printed immediately after the normal banner at startup, summing up the
evaluation of all input sources (commandline, xcontrol, xtbrc). To check
this warnings exclusively before running an expensive calculation a
input check is implemented via the *--define* flag. Please, study this
warnings carefully!

After `xtb(1)` has evaluated the all input sources it immediately enters
the production mode. Severe errors will lead to an abnormal termination
which is signalled by the printout to STDERR and a non-zero return value
(usually 128). All non-fatal errors are summerized in the end of the calculation
in one block, right before the timing analysis.

To aid the user to fix the problems generating these warnings a brief
summary of each warning with its respective string representation in the
output will be shown here:

*ANCopt failed to converge the optimization*::
   geometry optimization has failed to converge in the given number
   optimization cycles. This is not neccessary a problem if only a
   small number of cycles was given for the optimization on purpose.
   All further calculations are done on the last geometry of the
   optimization.

*Hessian on incompletely optimized geometry!*::
   This warning will be issued twice, once before the Hessian,
   calculations starts (it would otherwise take some time before
   this this warning could be detected) and in the warning block
   in the end. The warning will be generated if the gradient norm
   on the given geometry is higher than a certain threshold.

EXIT STATUS
-----------
*0*::
   normal termination of `xtb(1)`

*128*::
   Failure (termination via error stop generates 128 as return value)
