M-1 experiment: `string: potential evaluations` of the GFN2 ammonia inversion string
command: xtb nh3_up.xyz --gfn 2 --lts --lts-method string --lts-product nh3_down.xyz
         --lts-string-nnodes 16 --lts-frms-avg 1e-5 --lts-frms-max 1e-5
         --lts-max-steps 200 --norestart --namespace p3
(the tight criterion is needed so that the climbing node loop -- the only reader of
 `n_eval` -- actually iterates: 34 iterations here)

code version | build flags                                  | potential evaluations
-------------+----------------------------------------------+--------------------
pre-fix      | (default Release)                            | 11246
pre-fix      | -finit-local-zero                            | 11246
pre-fix      | -finit-local-zero -finit-integer=-1          | 11212   <-- UB: depends on the build
fixed        | (default Release)                            | 10685
fixed        | -finit-local-zero                            | 10685
fixed        | -finit-local-zero -finit-integer=-1          | 10685
-------------+----------------------------------------------+--------------------
reading: the pre-fix counter is not reproducible across builds (11246 vs 11212) because
`n_eval` was read before it was assigned; the fix assigns it on entry and per iteration,
so the value is identical in every build.  The fixed value is also 561 lower (5.2 %)
because the old accumulation `string%n_eval = string%n_eval + n_eval` sat inside the loop
while `n_eval` was cumulative, i.e. the diagnostic double counted the line search trials.

side observation: -finit-integer=<nonzero> is not usable on this code base as a whole - a
plain `xtb h2o.xyz --gfn 2` segfaults with it (a pre-existing core issue, independent of
the landscape tree); -finit-integer=-1 is the variant that survives here.
